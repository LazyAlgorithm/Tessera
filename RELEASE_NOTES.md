# Tessera v0.1.0-beta.1

Early beta of the Tessera engine, project launcher, and editor for Linux x64 and Windows x64.

- Portable folders with a launcher at the top level, engine assets, project templates, shader compiler, and the source/native libraries required to compile game scripts.
- Cross-platform Python packaging, also available through the editor's Build window.
- Windows process hardening preserves the original process access list and restores it during shutdown. Ringfall/Steam compatibility still needs testing with hardening enabled.

Start `Tessera` on Linux or `Tessera.exe` on Windows. BeefBuild and Python 3.11+ are required to edit/build projects. Windows also needs Microsoft C++ Build Tools. Graphics drivers and normal operating-system libraries are prerequisites.

Since v0.1.0-beta.1: scripts reload while the editor runs on Windows as they do on Linux (tested under Wine; not yet on a Windows machine).

Also since v0.1.0-beta.1:

- Faster scenes. Destroying an object no longer looks through every field of every component by reflection (a frame destroying 30 objects in a scene of 4,000 components went from about 200 ms to under 1 ms), each class's fields are worked out once, `FindComponent` and the per-frame audio, wind, spawn and navigation lookups use an index by class, shadow draws of the same mesh are batched together again, a missing model is no longer looked for on disk every frame, an animated model that nothing draws (off screen, too far away to cast a shadow) is bent only every eighth frame (on a dedicated server not at all) while its animation keeps playing, and voxel terrain works out which chunks it wants only when a viewer moves a quarter of a chunk or a setting changes.
- `Application.Quit()`: a game's quit (or `Running = false`) closes a built game and stops Play in the editor, with no change to game code.
- Destroying an object (or unloading a scene) tells every component under it that it is going before any object is freed, so a component's `OnUnregister` can still look at its children: an IK component on a rig no longer crashes when its scene is unloaded.
- One code style across the engine, applied by `tools/format/format_code.py` (`docs/coding-style.md`).
- The code was restructured for reading and changing: long methods (the longest were 300 to 700 lines) are split into named steps, large classes (voxel terrain, networking, rendering) are split into files by area, repeated code is shared, constants are named, and the commonly used API has doc comments. No public API was removed or renamed: games build unchanged.
- Hinge joints with a motor and spring suspensions (`Scene.Physics.CreateHinge`, `CreateSuspension`), and cylinder and convex hull parts in a Compound Collider (`docs/joints.md`).
- Map Builder: built-in Primitives, Walls and Floors folders in every project (walls, doorways, windows, pillars, floors, ramps, stairs and platforms with colliders), and a model a prefab already places is listed once, as the prefab.
- Maps: `MapFiles.Export` writes a scene and its terrain sculpting as one `.tmap` file (a game's own map editor saves with it); `MapFiles` finds, checks (whole, made for this game, made with this format or older, no missing components or files, no duplicates) and mounts them, so a game can list them in its menu and play them without a new build (`docs/maps.md`). `PackFile` reads and writes a single pack from Beef; `GamePaths.GameFolder` is the game's own folder; `AssetPack` can serve files from memory.
- Map requirements: a game's `src/MapRules.txt` says what a map needs ("need 4 Tessera.SpawnPoint", optionally with a field test such as `raceOrder >= 0`). Saving a scene that breaks a rule opens a Map Warning window listing what is missing, with a button to mark a scene as not a map; `MapFiles.Find` refuses such a map. A `most` rule sets a limit ("most 500 Tessera.Rigidbody").
- Maps made in a game: `MapFiles.Export(scene, group, file, keepId, ...)` saves only a loaded level (`SceneSerializer.SaveGroup`) and keeps its Id when it is saved again; files the scene names under `.maps/<Id>/` (models a player brought in, kept with `AssetPack.AddMemoryFile`) go inside the map, and load from it, models included, once it is mounted. Each map has its file's `Hash`. `Mount(map, true)` opens an unfinished map for editing. `MapPieces` (the built-in walls, floors and primitives) moved from the editor into the engine, so games can use them. A texture named `model.glb#image0` is read from inside that model.
- Map downloads: `MapSharing` sends the host's map to a player who lacks it or has another version, in acknowledged 16 KB pieces, checks the hash, and writes it into the Maps folder (replacing the old version).
- Character customizers: a Skinned Mesh Renderer's parts can be hidden (`hiddenParts`, `SetPartHidden`), dyed (`partColors`, `SetPartColor`) or drawn only into shadows (`shadowOnlyParts`, a first-person player's own head); `MeshRenderer.Part` has `hidden`, `tint` and `shadowOnly` (`docs/skinned-materials.md`).
- Fonts: UI documents take `font-family: Fonts/X.ttf`, and `UIFonts.Push` draws immediate-mode interfaces in any .ttf or .otf in the project. `ImGui.DrawImage` takes a tint colour.
- Clip libraries: a Skinned Mesh Renderer's `clipLibrary` names other rigged files whose clips it can play, matched by bone name (`SkinnedModel.ImportClips`; `docs/animator.md`).
- Retargeting: a Clip Library made for another humanoid is retargeted through each model's bone map (`SkinnedModel.HumanMap`, matched by name for Mixamo, Synty, Unreal, Rigify and other naming styles, fixed in the Bone Map window and saved as a `.bonemap` beside the model). Rest poses (A and T), bone rolls, sizes and facings may differ, and the hips' movement is scaled by leg length, also for libraries on the same skeleton (`docs/retargeting.md`).
- Posing characters in the editor: bones drawn in the Scene view through the mesh and clickable (the toolbar's Bones button), the Animation window's Rig menu (Set Up IK Rig, Snap IK Targets to Bones, Bake IK Into Keys, Copy Model Clip Into This Clip), IK targets and poles drawn as handles, and the Hand Posing window (finger shapes and curls, Key Fingers, Copy to Other Hand). A Hand Pose curls a POLYGON hand's merged "finger" chain as the middle finger. `Gizmos.OnTopLines` / `OnTopTriangles` draw over everything in the Scene view.
- Physics prediction: clients simulate the server's physics bodies themselves, in step with their own player, instead of showing them in the past. A crate the player walks into moves the tick they touch it; a body only physics moves needs no correction (the physics is deterministic); a body another player shoves is put right by going back and running the ticks since again, bodies and player together. Predicted bodies are sent with exact speeds while they move, keep sleeping on the client, and are not moved back by lag compensation. On by default (`NetworkManager.PredictPhysics`); `NetworkIdentity.physicsPrediction` chooses per object (Auto leaves out objects with a Network Behaviour). See `docs/networking.md`.
- Decals: the Decal component (texture, colour, size, opacity, metallic and roughness, angle limit, unlit, order) projects a picture onto the solid scene inside its box, lit by the same lighting as meshes (now shared in `Engine/shaders/include/lighting.sh`); **GameObject > Decal**, **Stick to Surface** and box picking in the editor; `Decals.Spawn` / `Decals.Clear` for pooled short-lived decals made on every machine (`docs/decals.md`). A RenderView now uses 34 view ids (a decal view; the depth pass comes straight after the scene).
- Dialogue and subtitles: `.tdialogue` files (speakers; nodes of lines, answers, variables, events, jumps, each with an optional condition) edited in the **Dialogue** tab (Project > + > Dialogue, with a preview that plays any branch); the **Dialogue Runner** component shows lines as subtitles with their voice recordings, answers as buttons, takes keyboard, mouse and controller input, keeps its variables and place in saves, and with **Shared** is run by the server for every player. `Subtitles` shows the cues of an `.srt` file beside any sound an Audio Source plays (captions for sounds when the player wants them) and lines from code, with player settings for size, background, names and captions (`docs/dialogue.md`). `ImGui.InputTextMultiline`.
- Sequencer: `.tsequence` timelines (Transform, Camera shots with blends, Animation, Audio, Show / Hide, Event, Subtitle and Fade tracks) edited in the **Sequencer** tab (Project > + > Sequence; scrub or play the preview on the scene, Look Through Shots, K keys the selected object) and played by the **Sequence Player** component (pause, skip, seek, loop, Restore When Done, saving; Shared sequences timed by the server). `Scene.CameraOverride` and `Scene.ViewCamera` pick the camera the game is seen through; `NetworkSync.Quiet` (`docs/sequencer.md`).
- **Reflections**: shiny surfaces mirror the sky (a cube made from the scene's sky, blurrier for rougher surfaces) and **Reflection Probes** (GameObject > Reflection Probe: a box per room, captured from a point, with box projection and blending); Ambient From Surroundings takes ambient light from them (image-based lighting); Reflections in the scene's Lighting settings; Reflection Probes and Reflection Size in the quality presets; `--no-reflections` (`docs/reflections.md`).
- **Probe placement**: Place Probes in Window > Lighting (and `--place-probes`) looks at the scene and places reflection probes (each room with something shiny in it, boxed to its walls; doorways; shiny floors; open ground) and **Light Probe Volumes** (closer baked light probes in rooms, under roofs and wherever light changes over a short way), previewed in the Scene view before they are made, tagged so that placing again replaces only them (`docs/probe-placement.md`). Light Probe Volumes can also be added by hand (GameObject > Light Probe Volume). A draw now takes a reflection probe whose light reaches its middle before one it only reaches into.
- **Texture mipmaps and compression**: every texture gets mip levels (colour in linear light, normal maps kept unit length) and anisotropic filtering, so distant and slanted surfaces stop shimmering; built games get BC1 / BC3 `.ktx` copies of their pictures (a quarter to an eighth of the video memory), with Compress textures in the Build window; Texture Detail and Anisotropic Filtering in the quality presets; `--no-mipmaps`, `--no-compressed-textures` (`docs/textures.md`).
- Networking: ENet's packet throttle no longer drops snapshots and voice at random when a connection's round trip jitters (other players stuttered on Wi-Fi or busy machines; seen as flaky networking tests on CI).
- **macOS** (Apple silicon, Metal): the engine, editor and games build and run on a Mac (`docs/macos.md`); a macOS CI job runs every test fixture there and packages the editor; `build_player.py` and `package_engine.py` take `--platform macos`, File > Build on a Mac builds macOS and web games; `tools/macos_link.py` writes a project's macOS link settings; `tools/run_tests.py` runs the fixtures on any system.
- **Graphics quality presets**: `Quality.Set(.Low/.Medium/.High/.Ultra)` sets render scale, antialiasing, shadows, screen effects, LOD and foliage distance, GPU skinning and vsync at once; the player's choice is saved (`Quality.Save`) and applied at start; `Quality.Recommended`, `--quality`, and Window > Graphics Quality in the editor (`docs/quality.md`). High is the previous defaults.
- **LOD Group**: levels of detail picked per camera from how much of the screen an object covers, from `_LOD0`..`_LOD3` children or simplified meshes made at load, with Cull Below, `LODGroup.Bias`, Inspector Preview and `--lod-level` (`docs/lod.md`).
- **Occlusion culling** (Camera > Occlusion Culling): what is wholly hidden behind big solid objects is not drawn, from a small CPU depth picture made each frame; Mesh Renderer **Occluder** Auto / Always / Never; Window > Scene Occlusion Culling and Occlusion Picture in the editor (`docs/occlusion-culling.md`).
- **GPU skinning**: skinned models are bent by a compute shader on the graphics card, into the vertex buffers every pass uses; CPU fallback where compute is missing, `gpuSkinning` per model, `GpuSkinning.Enabled` and `--cpu-skinning` (`docs/gpu-skinning.md`). `Mesh.Vertices` of a GPU-skinned model stay at rest.
- Behaviour trees: **Run Subtree** runs another tree file in place (shared blackboard, shown live, Open / New Subtree File in the Behavior tab, loops refused), and tree files are read once and shared by every runner; **Event Received** / **Send Event** with `runner.SendEvent` and `OnTreeEvent`; hearing with `AINoise.Make` and **Heard Noise**; `#Tag` instead of a name in Can See, Is Near and Move To Object; Can See **Sight Points**; **Set Number**, **Compare Number**, **Remember Position** and the runner's **Start Values**; **Chance**, **Random Selector**, **Run Once**; Wander picks reachable points; Ctrl+D duplicates nodes (`docs/behavior-trees.md`). Older tree files load unchanged.
- Navigation: agents go straight at any angle where they can (**Smooth Path**, keeping the grid's clearance); **Navigation Link** (jumps, ladders, teleporters, one-way drops, with `OnLinkStarted` / `OnLinkFinished`), **Navigation Obstacle** (carves the grid while still, steered round while moving; left out of bakes), **Navigation Area** (costly or blocked ground); agents steer round each other (**Avoid Others**, **Radius**, **Avoidance Priority**); `SamplePosition`, `RandomPoint`, `Raycast`, `FindPath` with the links each leg crosses, `RemainingDistance`, `Velocity`; Inspector tools (Drop Ends to Ground, End at View Centre, Fit to Object), gizmos for carved and costly cells, links and agents' paths; editor switch `--bake-navigation` (`docs/navigation.md`).
- Fixed: the anti-cheat message used the same id as network events (247), so in games with anti-cheat on, events sent with `NetworkSync` were handed to the anti-cheat instead; it is 243 now, and `Tests/Network` checks the engine's message ids are all different.
- Editor test switches `--save-scene`, `--camera "x y z yaw pitch"`, `--dialogue <file>`, `--sequence <file>`, `--sequence-time <seconds>`, `--rig-test`, `--ik-rig`, `--hand-shape <shape>`, `--hand-posing` and `--bone-map`.
- Fixed: Map Builder and Project panel thumbnails each showed the asset made before it (and the first none), because the picture was copied before the preview's last render pass.
- Fixed: the editor's Input Actions window crashed on an action with a touch binding, and touch bindings could not be put on direction actions.

Known limitations: macOS and browser exports are not supported. This is an early beta; back up projects before use.

Validation: Linux package creates a project and that project compiles using the packaged engine/editor and native archives. Windows packages require a native Windows launch/create/build smoke test before release validation can be claimed.
