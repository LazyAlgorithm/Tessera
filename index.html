Everything a small team needs

One editor, one language for engine and game code, and the systems a multiplayer 3D game needs, already working together.

Rendering

bgfx with forward HDR, four shadow cascades, flat shading for the low-poly look, bloom, fog and a procedural sky.

Voxels

Smooth, contoured terrain you can dig and build at run time, with painted grass and trees that bend in the wind, and objects that break into physics pieces.

Physics

Jolt rigid bodies, colliders, ray and shape casts, joints, and a character controller that climbs steps.

Networking

Server-authoritative sessions with prediction, interpolation and lag compensation. Mark a field [Sync] and it is shared.

Input actions

Ask for “Jump”, not Space. Keyboard, mouse, Xbox, PlayStation, Switch pads and touch screens, from one file.

Visual scripting

Graphs compile to ordinary Beef components, with about 1,550 engine nodes read straight from the source.

Interfaces

HTML-like .tui documents with stylesheets, a live UI editor, and immediate-mode GUI for HUDs.

Shipping

One executable and one packed asset file for Linux and Windows, or a web page with join codes for the browser.

Multiplayer

Write one tick. Play it on every machine.

  • Your player is a NetworkScript. Fill in OnTick with what happens in one sixtieth of a second, reading controls only from its TickInput.
  • The engine runs it on the server and, at once, on the player's own machine. When the two disagree, it rewinds and replays the missed ticks, then eases the difference away.
  • Everyone else is drawn a moment in the past, gliding between snapshots. Shots are judged against what the shooter saw.
  • With no session in the scene, the same script simply runs offline.

From nothing to a running game

Install the editor, make a project, write a component, and build an executable you can send to someone.

Create a project

  1. Start Tessera (Tessera.exe on Windows). The launcher lists recent projects.

  2. Choose to create a project, give it a name and a location. The name becomes the namespace of your scripts.

    Tick Include sample for a voxel world and a networked player to look at.

  3. Press Create Project. The scripts compile and the editor opens.

The Project window shows the project's Assets folder, which is src/ on disk. Every script anywhere in it is compiled. Scripts/GameSetup.bf runs once at start-up, before any scene loads.

Components receive Awake, OnEnable, Start, FixedUpdate (60 times a second), Update, LateUpdate, OnGUI, OnDisable and OnDestroy. Fields can be float, int32, bool, vectors, Quaternion, Color, String and enums marked [Reflect(.All)]. [Range(min, max)] gives a slider; [HideInInspector] hides one.

Play and change it

Press Play. The cube turns 45 degrees a second. While it plays, change degreesPerSecond in the Inspector, or edit the script and save: scripts reload while the editor runs, without stopping. File > Reload Scripts (Ctrl+R) forces a reload. Changes to the engine itself need File > Full Rebuild & Restart.

Build the game

Choose File > Build..., pick Linux, Windows or Web and a folder, and build. A desktop build is one executable, one asset pack (game.tpak, compressed and checksummed) and a licence file, so the folder can be zipped and sent. The same is available from a terminal:

A built game takes --host, --server and --connect <address> for multiplayer. More in the shipping section of the manual.

Tutorial series · Arena shooter

Build a multiplayer arena shooter

A first-person shooter for two to eight players, built in eight slices. Each slice adds one thing and ends with a game you can play.

You will write two components. Player walks, looks, shoots and draws its own HUD; Health goes on anything that can be shot. The player derives from NetworkScript from the start, which costs nothing offline and means that going online in slice 6 is a matter of adding a session and saving a prefab.

Before you start

  • Tessera installed, and a project created from the launcher with no sample. Call it Arena; the code below uses that namespace.
  • Two short sound files for slice 5, a shot and a reload, in WAV, OGG, MP3 or FLAC.
Why slicesEach slice is small enough to finish in a sitting and leaves the game working. If something breaks, the last slice is the place to look.

Slice 1 of 8

The arena

Goal A walled floor, some cover, light, and places for players to appear.

  1. Choose GameObject > Plane for the floor. Scale it to about 4 × 1 × 4 so it is 40 metres across.

  2. Add GameObject > Cube four times for the walls: scale each to 40 × 4 × 1 and move them to the edges. Add a few more cubes as cover, 2 to 3 metres tall. Check that each has a Box Collider in the Inspector, and add one from Add Component > Physics if not.

  3. Make sure the scene has a Directional Light (GameObject > Directional Light) and a Camera. Turn on fog and bloom with nothing selected in the Inspector if you like the look.

  4. Add four GameObject > Spawn Point objects, one in each corner, facing the middle. Each draws a ring, a post the height of a person and an arrow.

  5. Save the scene as Scenes/Arena.tscene.

Check itPress Play and fly the Scene view around. Nothing moves yet, but the walls cast shadows and the spawn points face inward.

Three things in this script matter later:

  • OnTick reads controls only from input, never from Input. Online, the server runs it with each player's controls, and the player's own machine runs it again after a correction.
  • Movement goes through the CharacterController. That is the state the engine corrects when the server disagrees.

Check itPress Play and click the Game view. You walk, jump onto low cover, and look around. Esc frees the mouse; click to take it again.

Slice 3 of 8

Shooting

Goal Hold the left mouse button to fire. Targets lose health and break.

Hits are decided with a ray from the eyes. Damage goes to a separate Health component, so the same code hurts targets now and players later.

Then add firing to the player. The highlighted lines are new:

  1. Add a few cubes in the arena as targets and give each a Health component.

  2. Give the player a Health too, with Respawns ticked. You will need it in slice 4.

Firing happens inside if (IsServer). With no session this machine counts as the server, so it works now. Online, only the server decides what a shot hit, which is what stops a player from claiming hits that did not happen. The ray starts just in front of the eyes so it does not hit the shooter's own capsule.

Slice 8 of 8

Ship it

Goal Zipped builds for Linux and Windows, and a link anyone can open on a phone.

Desktop

File > Build..., choose Linux, then again for Windows. Each folder holds the executable, game.tpak and the licence file. Zip the folder and share it. Players host with --host or join with --connect <address>; a menu can do the same from code later.

Web

Choose Web in the Build window. The first time, it shows a set-up command to run once. The result is a folder with index.html that any static host can serve, such as GitHub Pages. In a browser:

  • The session uses WebRTC. A host gets a six-letter room code and a join link, and players connect directly, with no server or port forwarding.
  • Touch screens get on-screen controls bound to the same input actions.
  • Settings and saves are kept in the browser's storage.

See Put your game in a browser for the details.

Where to take it next

  • Bots: a Navigation Agent walks the arena and a behaviour tree decides when to chase. See the Behavior tab.
  • Teams: set Team Count on the session and give spawn points a team.
  • Weapons that differ: move damage, fireInterval and magazineSize into a small class per weapon.
  • A real menu with host and join buttons, built as a .tui document.
DoneYou have a networked shooter with prediction, lag-compensated hits, synced health and ammo, respawns and a scoreboard, in two scripts.

How Tessera works

The parts you will use most, with the calls that drive them.

Components and scenes

A scene is a tree of GameObjects; each has a Transform and any number of components. Components are Beef classes marked [Component]. Public fields are saved and shown in the Inspector.

  • GetComponent<T>() and AddComponent<T>() on an object; Scene.FindComponent<T>() for the first in the scene.
  • Prefab.Instantiate(scene, "Prefabs/Crate.tprefab", position, rotation) places a prefab; Scene.Destroy(obj) removes an object.
  • SceneManager.Load changes scene; LoadAdditive and Unload add and remove levels kept in their own scene files.
  • SpawnPoints.Next, Random and Place choose among the scene's spawn points, by team.
  • Application.Quit() quits: a built game closes, and in the editor Play stops and the editor stays open, so a menu's Quit button needs no special case. Setting Application.Instance.Running = false does the same. Application.Instance.Close() always ends the program.
  • Scene.DestroyImmediate(obj) takes the whole tree down at once: every component in it gets OnUnregister before any object is freed, so a component can still look at its children as it goes.

Touch screens

On a phone or tablet the game draws its own on-screen controls, made once with TouchControls and bound in Input.tinput like any other control (bind touch Fire), so the game reads them as it reads keys or a controller. A touch control can be bound to any action, buttons and directions alike, so a stick can drive Move directly.

CallMakes
AddStick(name, area, anchor, offset, radius)A thumbstick that appears where the thumb lands in area. Set hideWhenIdle and it is drawn only while used.
AddLook(name, area)An area to drag across to turn the view, like the mouse.
AddButton(name, label, anchor, offset, radius, dragLooks)A round button; with dragLooks, dragging on it also turns the view, so one thumb fires and aims.
AddSwipe(name, source, direction)A quick flick across another control, down for one frame as the finger lifts. A slow drag is never a flick, and the view is held still while a stroke could still become one.

Places are an anchor on the screen plus an offset in screen units, the screen's short side, so one layout keeps its shape on any phone and either way up; move controls for portrait by changing offset. Each control has visible, dimmed (faded but in place, so a layout never shifts under the thumb), lit (a switch that is on) and label. TouchControls.Scale sizes everything and EdgeMargin keeps it in from the edges. Ringfall's controls are a worked example: a hidden-until-used stick on the left, and every action in an arc around FIRE on the right.

Physics and joints

A Rigidbody with a collider (Box, Sphere, Capsule, Mesh, Convex Hull or Compound) is simulated by Jolt. Scene.Physics answers Raycast, SphereCast and OverlapSphere. A Compound Collider is built from parts in the object's own space: AddBox(center, size), AddCylinder(center, radius, halfHeight, rotation) and AddHull(center, points, rotation) (the convex hull round four or more points); call Rigidbody.RebuildBody afterwards.

JointMade withUse
BallThe Joint component, or Joint.Connect(a, b, anchor, axis, swingLimit)Chains, lamps, ragdoll limbs; a swing limit in degrees makes a shoulder or a hip.
HingeScene.Physics.CreateHinge(bodyA, bodyB, anchor, axis, childAxis, childNormal)Doors, wheels, arms. SetHingeMotor spins it (mode 1, radians a second) or turns it to an angle (mode 2); HingeAngle reads it.
SuspensionScene.Physics.CreateSuspension(bodyA, bodyB, anchor, childAnchor, axis, childAxis, childNormal, travel)A slider with travel metres either way. SetSuspensionSpring(joint, stiffness, damping) (newtons a metre, newton-seconds a metre); SuspensionPosition reads it.

Hinges and suspensions take body ids (rigidbody.BodyId), with the anchor and axes in world space, and return a handle; DestroyJoint removes one, and destroying either body removes it too. Bodies joined by a hinge or a suspension do not collide with each other, so a wheel can sit inside its arch.

Turn on Debris on a Rigidbody for things that should lie about without getting in the way: characters, other bodies, rays and casts all pass through it. Joints are local to each machine, so in multiplayer create the same ones everywhere; Joint components saved in a scene or prefab already are.

Networking

Add a Network Session and the scene is multiplayer; without one nothing changes. The server runs the game from each player's controls and sends the result.

Shared with no codeRule
Physics bodies, characters, AIMotion is shared; AI thinks on the server.
Voxel terrain and objectsEdits applied everywhere in the server's order; late joiners catch up.
Animation, sound, materialsStarted by the server or the object's owner, seen and heard everywhere.
Prefabs with a Network IdentityInstantiated on the server, they appear on every machine.
[Sync] fieldsThe server's value, sent reliably when it changes.
Network eventsSendNetworkEvent("name", value) runs OnNetworkEvent on every machine.

For a player, derive from NetworkScript and fill in OnTick. Three rules keep prediction working:

  1. Take controls only from the TickInput, never from Input.
  2. Move the object through its Transform, Rigidbody or Character Controller; that is the state that gets corrected.
  3. OnTick can run more than once for one tick on the player's machine. Do one-off things inside if (IsServer) or if (!IsReplaying).

A shot is judged against what the shooter saw by wrapping its ray cast in BeginLagCompensation() and EndLagCompensation(), up to 24 ticks back. NetworkManager.RegisterMessage with SendToServer, SendToAll and SendToClient carries any other game event. Scene.Network.Kick(clientId) removes a player.

TrafficSize
Controls, client to server9 bytes a tick, 1 byte when unchanged; about 1–2 kB/s
Snapshots, server to client20 a second, 12–15 bytes per changed object
A still sceneAbout 0.3 kB/s per client

Testing on one machine

Start the same build twice. No second build is needed.

--lag <ms>, --jitter <ms> and --loss <percent> simulate a poor connection; use the same values on both. --netstats prints bytes, corrections and buffered ticks every second.

Rendering and materials

A forward HDR pipeline on bgfx: four shadow cascades from the sun, up to 16 point and spot lights (spot lights cast real-time shadows), metallic/roughness shading, per-triangle flat shading, fog, bloom and tonemapping. Identical mesh and material pairs are instanced automatically.

  • Materials (.tmat) are shared between objects and edited live in the Inspector.
  • Shader graphs make shaders without code; .tshader surface shaders keep the engine's lighting, shadows and fog.
  • Compute shaders (.tcompute) run per pixel, usable with no script through the Compute Effect component.
  • Models: glTF and GLB, with skinned characters and Animator Controllers (.tcontroller) for state machines.

First-person viewmodel

A first-person player's arms and weapon are drawn in a pass of their own, after the world and over it, with their own field of view and a near clip at the eye: a gun never pokes into a wall it is held against, and keeps its shape however wide the world's field of view.

  1. In Project Settings, name a layer Viewmodel and untick it against every layer in the collision table.
  2. Make the arms and weapon children of the camera's object and put each part on that layer (the Layer menu at the top of the Inspector).
  3. On the Camera, pick Viewmodel Layer, and set Viewmodel Field Of View, Viewmodel Near Clip and, if you want the gun's shadow on the world, Viewmodel Casts Shadows.

With the camera selected the Scene view shows the viewmodel's view in amber, next to the camera's own; place the arms and weapon inside it. The viewmodel is lit, fogged and shadowed like the world. It needs no networking: only each player's own camera draws it, and everyone else sees that player's full body as usual. From code: camera.viewmodelLayer = ProjectConfig.LayerNamed("Viewmodel"). Any component can show an integer as a choice of layers with [Layer].

A Viewmodel Pose on the arms-and-weapon object moves it: from a hip pose to an aim pose in the middle of the screen while aiming is set, a walk bob and a sway when the view turns (both worked out from the camera's movement, and steadier while aiming), and recoil with Kick(). In the Inspector, Preview blends hip to aim while editing, and Use current place as Hip / Aim take the object's place as a pose.

Decals

On the dev branchDecals are on dev and not yet on main or in a packaged build.

A Decal presses a picture onto whatever solid surfaces lie inside its box (posters, signs, road markings, cracks, scorch marks), following their shape and lit and shadowed like them, with no change to their models or UVs.

  • GameObject > Decal makes one stuck to the surface in the middle of the Scene view. The picture is pressed along the object's blue (forward) axis; the Scene view draws the box, and clicking inside it selects the decal.
  • Stick to Surface, under the component, moves it onto the surface it points at (or the one below) and lays it flat, keeping the picture the same way up.
  • Set Texture (a PNG whose alpha decides where it shows), Color, Size (width, height and depth in metres), Opacity, Metallic and Roughness, Angle Limit (surfaces turned further away do not get it, so a floor decal does not run down the sides of boxes), Unlit and Order (higher draws over lower).

For marks that come and go in numbers, Decals.Spawn(Scene, point, normal, "Textures/hole.png", 0.12f, 20) makes one 12 cm across that fades out after 20 seconds. They are kept in a pool (Decals.MaxSpawned, 256 by default) that recycles the oldest, and Decals.Clear(Scene) removes them. A Decal component is part of its object like any other component; spawned decals are not sent over the network, so make them on every machine from code that runs on each, such as where a hit is announced. See docs/decals.md.

Dialogue and subtitles

On the dev branchDialogue and subtitles are on dev and not yet on main or in a packaged build.

Branching conversations live in .tdialogue files: speakers, and nodes of steps that run from the top. A step is a line someone says (with an optional voice recording), an answer the player can pick, a variable set or added to, an event for the game, a jump to another node, or the end, and any step can have a condition such as gold >= 10.

  • Project > + > Dialogue makes one and opens the Dialogue tab: nodes and speakers on the left, the selected node's steps in the middle, and a preview on the right that plays any branch with its answers, events and variables, without starting the game. The file is plain text, so it can also be written by hand.
  • Add a Dialogue Runner to the character who talks and pick the file. Each line shows as a subtitle with the speaker's name in their colour and plays its recording from the speaker's object; answers appear as buttons, picked with the mouse, number keys, arrows or a controller. Play On Start or Play() starts it; OnEvent tells your code when to open the gate or hand over the item.
  • Variables belong to the game and are kept in saves, with where the conversation was.
  • Shared makes one conversation for everyone in a co-op session: the server runs it, any player (or only the owner) can move it on or answer, and late joiners see where it is.

Subtitles also follow any sound an Audio Source plays that has an .srt file beside it, with [captions] for sounds shown when the player turns captions on. Subtitles.Show puts up a line from code, and the player's settings (on, captions, names, size, background) are there for an options menu. See docs/dialogue.md.

Sequencer (cutscenes)

On the dev branchThe sequencer is on dev and not yet on main or in a packaged build.

A sequence is a timeline for cutscenes, level intros, lifts and doors that open in stages: tracks that move objects, cut or blend between camera shots, play animations and sounds, show and hide things, fade the screen, show subtitles and fire events for the game. It lives in a .tsequence text file.

  • Project > + > Sequence opens the Sequencer tab. + Track adds a track (on the selected object where it needs one); double-click a row to add a key, drag keys along the ruler, and edit the selected key underneath.
  • Dragging the playhead puts the scene where the sequence has it, and Look Through Shots moves the Scene view's camera onto the camera shot. Move an object with the gizmo and press K to key it at the playhead. Stop Preview (or starting the game, or saving) puts everything back.
  • A Sequence Player plays it: Play On Start or Play(), Pause, Skip (events skipped over still happen) and Seek, with Loop, Skippable and Restore When Done. While a shot is on, the game is seen through it, then through its own camera again. Saves keep where it was.
  • Shared plays one sequence for everyone in a session on the server's clock; any player (or only the owner) can pause or skip it, and events happen on the server.

See docs/sequencer.md.

Navigation

A Navigation Surface bakes the walkable ground inside its box (or, with Flying, the open air) into a grid of cells, from the scene's static colliders and meshes; Bake & Save Navigation in the Inspector writes it to a .tnav file. A Navigation Agent finds paths across it: call SetDestination(point, speed, stoppingDistance) and watch HasArrived or PathFailed. It walks through the object's Character Controller or Rigidbody when it has one. In multiplayer the server moves agents.

On the dev branchThe features below are on dev and not yet on main or in a packaged build.
  • Straight paths: agents go straight at any angle where they can, keeping the grid's clearance from walls.
  • Navigation Link: a jump, ladder, drop or teleporter between two places the grid does not join, one-way or both, with a cost. Agents cross it when it is shorter and the game hears OnLinkStarted / OnLinkFinished to animate them.
  • Navigation Obstacle: something that moves (a crate, a car). Standing still it carves its shape out of the grid; moving, agents steer round it.
  • Navigation Area: ground that costs more to cross (mud, water) or that agents never enter.
  • Avoidance: agents steer round each other, with a radius and a priority.
  • Queries: SamplePosition, RandomPoint (for wandering), Raycast, RemainingDistance. The selected surface shows carved and costly cells, links are drawn as arcs, and agents draw their paths.

See docs/navigation.md; the Sandbox sample's Scenes/Navigation.tscene shows all of it.

Behaviour trees

A behaviour tree decides what an AI character does. Draw one in the Behavior tab (Project > + > Behavior Tree), give the character a Behavior Tree Runner and a Navigation Agent, and press Play: the tab shows the selected character's tree live, running nodes amber, successes green, failures red. Saving while playing reloads it on every character using it.

On the dev branchThe features below are on dev and not yet on main or in a packaged build.
  • Run Subtree: one tree file runs another in its place, with the same memory. Open it from the node, see it live, and share one Wander tree between guards, animals and villagers. Files are read once for every character.
  • Events: the game tells the tree something with SendEvent("Hit") and the tree's Event Received reacts; Send Event tells the game back (OnTreeEvent).
  • Hearing: AINoise.Make(scene, position, radius) for gunshots and footsteps, picked up by Heard Noise.
  • #Tag instead of a name to find targets; Can See can look for a target's head and feet behind low cover.
  • Numbers on the blackboard (Set Number, Compare Number), per-character Start Values, Remember Position, Chance, Random Selector, Run Once, and Ctrl+D to duplicate nodes.

In multiplayer, trees think on the server. See docs/behavior-trees.md; the Sandbox's Navigation scene has a guard that wanders and goes to look when it hears the crate.

Materials on skinned meshes

A rigged model with several materials (skin, cloth, armour) or any textures is drawn in parts, one per material in the file, each with the material saved there: base colour, normal, metallic-roughness, occlusion and emissive textures (inside a .glb, as data: addresses or as files beside the model), metallic, roughness, alpha mode and double sides. A model with one plain material is drawn as before, with its Mesh Renderer's settings.

The Inspector lists the parts under the Skinned Mesh Renderer by the file's material names; type a .tmat beside one to use it instead. A Material on the Mesh Renderer covers every part without one of its own, and the renderer's Color tints them all. From code, skinned.SetPartMaterial(index, "Materials/armour.tmat"), which is sent to every machine in a network session; PartCount and PartName(i) list the parts. The textures are named after the model (Models/hero.glb#image2), so your own materials can use them too.

Character customizers. When every outfit choice is a part of one model, parts can be hidden (Hidden Parts, SetPartHidden("Hat_Tricorn", true)), dyed (Part Colors, SetPartColor("Coat", .(0.5f, 0.1f, 0.1f))), or drawn only into shadows (Shadow Only Parts, for a first-person player's own head). All three are saved with the scene.

Clips from another file. Clip Library names other rigged files whose clips the model plays too, so characters can share one file of animations. See Retargeting and posing.

Animation layers and blend trees

Layers. An Animator Controller starts with a Base Layer for the whole body. More layers, added with + under Layers in the Animator window, are each a state machine of their own laid over the ones below: the upper body aiming or reloading while the legs run, or a recoil added on top of whatever plays. Each has a Weight (from code, animator.SetLayerWeight("Upper Body", 1)), Blending (Override replaces the pose of the bones its clips move; Additive adds what its clips do) and a Mask: the bones it may move, each named bone and everything below it (spine_02 for the upper body).

Blend trees. Select a state and choose Blend Tree instead of Clip to mix several clips by parameters: 1D along one (walk at 1, run at 3, by speed) or 2D over two (forward, left, right and back by the direction of movement). Clips play in step so feet stay together, and a picture shows each clip's share and where the parameters are, live while the game plays.

Both work with .tanim clips, and with a rigged model's clips when its Skinned Mesh Renderer has Expose Bones. In multiplayer, parameters and layer weights set by the object's owner reach every machine, and the owner's machine decides every layer's transitions.

Inverse kinematics

Inverse kinematics (IK) poses a limb from where its end should be: you say where the hand goes and the arm works out the elbow. It is a layer over the animation: clips play first, then scripts, then IK, so a walk cycle carries on underneath while the hands stay on a rifle that sways and recoils. Each component has a Weight from the animation (0) to the IK (1), gives the pose back untouched when disabled, and runs in the editor as well as the game.

ComponentDoes
Limb IKHolds a hand or foot on a target: hands on a weapon, a hand on a handle
Look At IKTurns a head, or a head with the neck and spine, towards a target, within a limit
Foot PlacementKeeps both feet on uneven ground and lowers the hips to suit
Hand PoseA curl slider for each finger, spread, trigger, and shapes: Open, Fist, Grip, Trigger, Point, Pinch

Hands on a weapon. Put two empty objects on the weapon where the hands belong. Add a Limb IK to the character for each arm: with Tip empty the Inspector lists the hands it finds, and the grip goes in Target. An object in Pole is where the elbow points. To turn the hand on the grip, set Weight to 0, rotate the hand, press Keep Hand's Rotation, and bring Weight back.

Each arm is its own component, so each lets go by itself: leftArm.LetGo(0.15f) sends that arm back to its animation to throw a grenade while the other stays on the grip, and leftArm.Grab(0.2f) brings it back. SetTarget(other, seconds) moves a hand to another grip without a jump.

Rigged models take part when Expose Bones is ticked on the Skinned Mesh Renderer: every bone becomes an object, which IK can turn, an Animator can play clips on, and a weapon can be parented to.

Animating with it. A target that is a child of the Animator's object is keyed like any other child. Key IK in the Animation window writes the pose IK is making into the clip, on every bone it moves. Recording keys a bone only when you move it by hand, not because IK is bending it.

From code, IKSolver.TwoBone, Chain and LookAt are the solvers themselves. In multiplayer IK is worked out on each machine; LetGo, Grab, FadeWeight and SetShape are followed everywhere when the object's owner calls them, and a target moves on other machines if it is shared like any other object.

Retargeting and posing characters

Clips made for one humanoid play on another: a Mixamo run on a Synty character, a Basic Motions walk on your own rig. Put the other file in the Skinned Mesh Renderer's Clip Library; its clips are listed with the model's own, marked (library), and play like any other. A library made for the same skeleton is matched by bone name. Any other humanoid is retargeted: each bone is swung to point the way its counterpart points at rest, so an A-posed clip fits a T-posed character, then turns as its counterpart turns in the model's space, so bone names, rolls, lengths and facings may all differ. The hips' movement is scaled by leg length, so a smaller character takes a smaller stride.

Bone maps. Every rigged model knows which of its joints is each humanoid bone (hips, spine, neck, head, arms, legs, three segments of each finger), matched by name for Mixamo, Synty POLYGON, Unreal, Rigify and other naming styles. Twist bones, IK helpers and end points are skipped. Bone Map... under the Skinned Mesh Renderer opens a window with a drop-down of joints for each bone. Clips update as you change it, and Save writes Models/hero.bonemap beside the model, which goes into builds with it. From code: model.HumanMap[.LeftHand].

Posing bones. With Expose Bones on, a selected character's bones are drawn in the Scene view through the mesh: blue on the left, red on the right. Click one to select it; the handle switches to Rotate. With Record or Auto Key on, turning a bone keys it. The toolbar's Bones button hides them. They are editor-only.

Animating with IK. The Animation window's Rig menu has Set Up IK Rig: a target box for each hand and foot (each with a Limb IK), a pole for each elbow and knee and a look target for the head, placed where the character is so nothing moves until they do. Record, move the marker, drag a box, and the limb follows and the box is keyed. Snap IK Targets to Bones moves the targets to where the clip puts the hands and feet. Bake IK Into Keys writes the IK pose into the bones on every frame. Copy Model Clip Into This Clip turns one of the model's own clips, retargeted ones included, into keys you can edit.

Hands and fingers. The footer's Hands button opens Hand Posing: shapes (Open, Relaxed, Fist, Grip, Trigger, Point, Pinch, Thumbs Up), a curl slider for each finger and Spread, Key Fingers, and Copy to Other Hand. While recording, a finished change is keyed by itself. POLYGON hands, whose last three fingers are one chain, curl it with Middle.

Nothing extra is sent in multiplayer: retargeting happens on each machine as models load, and the Animator sends clip and state. Full details in docs/retargeting.md.

Terrain

A Voxel Terrain is a grid of tiles, flat until sculpted with Raise, Lower, Smooth, Flatten and Paint. While a brush is picked the Scene view shows a preview under the mouse: the brush's edge lying on the ground, and a see-through mesh of the shape it is about to make. Generating ground is the game's own business, done from code with a [TerrainGenerator] class; the editor has no generation settings.

StyleSurface
ContouredDual contouring: one point in each cell joined into a regular grid of quads. Rounder and more even. The default.
SmoothMarching cubes. Choose it to go without dual contouring.
BlockyOne cube for each solid cell.

Contour Sharpness runs from the softest ground (0) to ridges and ledges kept crisp (1). Flat Shading shades every triangle flat for a faceted, low-poly look; off, the ground is shaded smoothly. A new terrain has a Voxel Size of half a metre, which with contouring and smooth shading passes for ordinary rolling terrain; 1 is coarser and lighter. Switching style moves nothing: sculpting, collision and networking work from the same samples.

Foliage and wind

A Foliage component is one kind of plant, many times over, drawn together by the graphics card so that tens of thousands cost little. On a terrain, press Foliage in the Terrain Tools, then + Grass, + Bush, + Tree or + Pine, and drag over the ground in the Scene view; Shift erases and Ctrl+Z undoes a stroke. Each kind of plant is a Foliage component on the terrain, where its Mesh (a built-in plant, or a model whose foot is at its origin) and the rest are set. On anything else, add a Foliage component and press Paint in it. Each plant gets its own turn, size and shade. Density is plants to the square metre, Max Slope leaves steep ground bare, and View Distance is how far they are drawn (they thin out towards it). From code: Paint, Erase, Add, Clear.

A Wind Zone blows the way its object faces: Global over the whole scene, or Sphere inside a radius, fading to the edge. Zones add up. Foliage bends by its Sway, and so does any Mesh Renderer with Wind Sway above 0 (a flag, a tree placed by hand). The bending is done on the graphics card, and shadows bend with what casts them. Grass also parts round anything walking through it: every object with a Character Controller pushes plants aside with nothing to set up, and a Foliage Bender (Radius, Strength) does the same for a creature, a vehicle or a boulder. Other players part the grass on your screen too, with nothing sent over the network. Wind.At(scene, position) reads the wind from code. Plants are scenery: no colliders, saved with the scene, the same on every machine.

Plants on a terrain follow its ground when it is sculpted: they ride it up and down, and are removed when buried or left with nothing under them, so none is left where nobody can reach it. Each is judged from where it stands, so grass on a cave floor stays put when the hill above is reshaped.

Destructible objects

A Voxel Object can be carved: voxels.Carve(point, radius) removes material where something hits it, and parts that are cut loose break off and fall as physics objects that can be carved in turn. In multiplayer a carve happens on every machine.

Any model can be one. Select an object drawn with a model, add a Voxel Object and press Make This Model Destructible: Shape becomes Mesh, and the model is filled in as solid material, keeping its size, colours and texture coordinates. The model must be closed, like a real object, with no open sides. It is re-made from a grid of Resolution cells (8 to 48) along its longest side, so parts thinner than a cell are lost and sharp edges soften a little. Sphere, Box and Cylinder are built in.

Materials. The outside is drawn with the object's Mesh Renderer material. The surfaces carving exposes are drawn with Interior Material when you name one (the wood inside a painted crate); otherwise with an inside made from the outside's material, the same textures carried through the solid, tinted by Interior Color and a little rougher; otherwise with plain Interior Color. Interior Tiling is how often the inside's texture repeats. Pieces that break off are made of the same stuff.

Anchored keeps an object in place (a wall, a cliff) so that only cut-off pieces fall; otherwise it becomes a physics body the first time it is carved.

Loading in the background

Scenes, models and textures can be loaded while the game keeps running: behind a loading screen, or a part of the world brought in as the player nears it. Files are read and decoded on loading threads; sending them to the graphics card is done a little each frame (AssetLoader.UploadBudget, 4 ms), so the frame rate holds.

Without code: add a Scene Loader, pick its Scene, and choose Additive (add it to the running scene) or not (change to it once loaded). Its progress field goes from 0 to 1, so a UI Document <bar bind="progress" /> on the same object is a loading bar. With Activate When Ready off it waits at 0.9 until Activate(), for "press any key to continue".

From code: SceneManager.LoadAsync(path) and LoadAdditiveAsync(scene, path) return a SceneLoad with Progress, CurrentStage, allowActivation and, for an additive load, Group. Every model and texture a scene names, through its prefabs and materials too, is loaded before it appears. AssetLoader.Preload("Models/launcher.glb", "Textures/launcher.png") gets anything else ready ahead of time. Every machine loads scenes for itself; nothing about loading is sent over the network.

Audio and voice

miniaudio is built in. Put an AudioSource on anything that makes sound and an AudioListener on the ears. Stereo panning or HRTF for headphones, distance rolloff, Doppler, occlusion behind colliders, reverb zones and six mixer groups. WAV, OGG, MP3 and FLAC.

Voice chat uses Opus and is off until you turn it on with VoiceChat.Enabled. The server decides who hears whom, for team-only or proximity voice. Push to talk works from any input action.

Interfaces

Two ways to draw an interface:

  • GUI from OnGUI: GUI.Label, Button, Bar, Box, Toggle, Slider. Quick, for HUDs and debugging.
  • UI documents: .tui markup with a .tcss stylesheet, laid out with flexbox and absolute positioning, edited in the UI tab, worked with a mouse, a controller's d-pad or a touch screen. See A main menu.

The UI tab lays a document out for the screen size chosen in its toolbar and draws the whole of it scaled to fit the panel. A canvas, which the game draws into, shows there as a named box: preview="Motion tracker" names it and preview-src="UI/tracker.png" shows a picture instead, both ignored while the game runs.

Fonts. font-family: Fonts/Title.ttf in a stylesheet sets the type of an element and what is inside it, from any .ttf or .otf in the project. From code, UIFonts.Push("Fonts/Title.ttf", 48) then ImGui.PopFont() draws a component's own interface in it, and ImGui.DrawImage takes a tint to fade or colour a picture.

Phones and tablets

One interface can serve a desktop, a phone held sideways and a phone held upright:

  • Design sizes. A UI Document's Reference Height (and Width) give the size it is designed for; it is scaled to fit whichever of the two is tighter, never stretched. UIDocument.SetVariant("phone", height, width) reads every document from a phone/ folder beside it where one exists, designed for that size; a game can give different sizes for portrait and landscape.
  • @media rules. A stylesheet can rearrange a document for its shape: @media (orientation: portrait) { #left { right: 24; width: auto } }, also min-/max-width, min-/max-height and min-/max-aspect-ratio, in the document's own units, tested on every layout so a turned phone rearranges at once. Give the parts that move an id or class: a style="" attribute wins over the stylesheet.
  • Web builds size the game to the browser's viewport inside the screen's safe areas, follow it when the phone turns (in fullscreen too), and draw the 3D scene at a resolution phones can keep up with while the interface stays sharp.

Add ?arg=--ui-debug to a Ringfall web address to see the size, pixel ratio, orientation and scale the game is working with.

Maps

A map is a level saved as one .tmap file that a game plays without being built again, so players can make levels and hand them to each other. Maps are made in the game, by a map editor the game provides, which saves with MapFiles.Export(Scene, level, "Maps/Harbour.tmap", mapId, "Harbour", author, description, problems): the level's objects, its terrain sculpting, and any model the player brought in. Models, prefabs, materials and scripts otherwise come from the game, so a map uses what the game has and never carries code. Pass the map's Id when saving it again, so players get the new version instead of a second map.

What a map needs. A game's src/MapRules.txt lists rules, one a line: need 4 Tessera.SpawnPoint "spawn points", a field test such as need 3 MyGame.Ring raceOrder >= 0 "race gates", or a limit, most 500 Tessera.Rigidbody "physics items". Saving a scene in the editor that breaks a rule opens a Map Warning saying what is missing (with This scene is not a map for scenes that are not). A game's map editor can show the same with MapRules.Check, and MapFiles.Find refuses a map that breaks one.

A game finds maps in the Maps folder beside it (the project's, in the editor), checks them, and plays one by mounting it and loading its scene:

Find returns every map, broken ones too, with Problems saying why one cannot be played: the file is not whole (every file inside has a checksum), it was made for another game or a newer engine, it uses a component or names a file the game does not have, or it is the same map (the same Id) as another. A game adds its own checks with AddProblem, and counts what is in a map with CountComponents. Tumble Toys: Aviation lists the maps from its folder after its own rooms.

Maps in multiplayer. Every player needs the same map. The host calls MapSharing.Offer(map). A player who lacks it, or has another version (checked by hash), calls MapSharing.Request(Scene.Network, id, hash): the map comes over in acknowledged pieces, is checked, and is written into the player's Maps folder, replacing an older version. MapSharing.State and Progress drive a download screen.

Known limits

  • The Windows editor has been run under Wine only (built games run on Windows), and Windows uses Vulkan only.
  • A client does not predict physics objects it does not own; a pushed crate moves when the server says so.
  • Skinned models are deformed on the CPU; no morph targets. A model no camera drew last frame is deformed only every eighth frame, and not at all in a headless server, so hidden crowds cost little.
  • Voxel terrain level of detail is for the Smooth and Contoured styles only; collision always uses full detail.
  • Only the ball joint is a component; hinges and suspensions are made from code, and only the hinge has a motor.
  • Objects placed from a prefab are copies; editing the prefab affects new placements only.

Working on the engine

The engine, editor and launcher are Beef, built with BeefBuild -workspace=. -config=Debug from the repository root. All of it follows one style, written down in docs/coding-style.md, and most of that is applied by a tool:

  • Tabs, braces on their own lines, one statement per line; a body goes on its own line, except a guard that only returns, continues or breaks.
  • Types, methods and constants are PascalCase; Inspector fields are camelCase; private fields start with m, static ones with s.
  • A method reads as a list of named steps, and is split once it passes about 80 lines; a large type is split by area into extension files (RenderViewShadows.bf, VoxelTerrainStreaming.bf, NetworkManagerClient.bf).
  • Public members get a /// comment saying what they do, which shows in code completion and on visual-scripting nodes.

Every test suite is a workspace under Tests/; run one with BeefBuild -workspace=Tests/<Name> -config=Debug -run.
